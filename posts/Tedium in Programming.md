# Tedium in Programming

2026-09-26

---
I've been reading many articles often relating to LLM usage or LLM disclosures. For many people taking the "middle ground" on their options about generative technology, I see the same phrase repeated over and over. 

> It's OK to use AI to do the tedious work.

I ask myself, what part of programming is tedious? Are you talking about the coding? If there is ever a situation that I'm coding, and I find myself doing tedious work it's often a chance to improve my situation rather than the moment to hand that work over to an LLM. In fact that's suppose to be the fun part! Automating or Optimizing tedious work is fun! I see boilerplate used as an example, write [snippets](https://github.com/SirVer/ultisnips)  or macros or code generators or something entirely new. Writing tests is often seen as lesser than, but I actually like doing that because A. it helps me understand my own code better, and B. catches bugs while I'm writing the test. A testing framework should make writing a test easy, sometimes it doesn't, which tells me that I should improve the testing environment, not that writing tests is bad.

These computer things(as in the computer itself) are suppose to work for us, not make us loose are brains.

I had a discussion with Software Engineer friend who works at *Microsoft* about search engines, and degrading quality of them. I was complaining about how a search engine will display a web based implementation of a tool rather than the tool that website is probably using, e.g. pdf editing, yt-dlp, network tools. My friend recommended asking an LLM instead. Which I mumbled, and half-heartedly agreed. Thing is, he's right, an LLM would probably give a better response, and would remove the **tedium** of having to find it myself using DuckDuckGo. Appending "bash" or "linux" or "stack overflow" on to all of my searches. However, instead of doing that I have increasingly taken to using other bespoke search enigines like [marginalia search](https://marginalia-search.com/), [the Nix package repository](https://search.nixos.org/packages), or just using specific website's search tools like [cppreference.com](https://en.cppreference.com/) which also has a [bang](https://duckduckgo.com/bangs). These produce better more specific results, and does not suffer from SEO optimization. Google, the ad company, has decided to side with the ads, and make searching worse, inorder to sell more ads. As a consequence Google made LLM more appealing as a method of discovery. However we cannot offload research onto a compression algrorithm in a trenchcoat. Research is not tedious work.
